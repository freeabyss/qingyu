## 剪贴板历史 · 方向三 玻璃（860×520，PRD 真实尺寸）

`clipboard-3.html` — 行内动作补齐，这是之前版本最大的缺口（列表只有缩略图和文字，没有任何可点动作）。

| 行类型 | 行内动作（从左到右） |
|---|---|
| 文本 / 图片 / 颜色 | 置顶 · 复制 |
| 文件（含目录） | 复制文件地址 · 打开文件所在目录 · 置顶 · 复制 |

- **置顶**：未置顶为描边图钉；已置顶行标题前加实心图钉标记，按钮变为「取消置顶」（实心 + 斜线，浅白底高亮）
- **复制**：行内图标；详情区头部另有带文字的「复制到剪贴板」主按钮（PRD：复制是带文字的主动作）
- **文件两项**：链环＝复制文件地址；文件夹＋右上箭头＝在 Finder 中显示（与缩略图的纯文件夹图标刻意区分）
- 筛选改回 PRD 要求的**下划线与字重反馈**（此前用了胶囊）
- 列表 499 / 详情 360，符合 860 宽的真实比例

图标全部为描边风格、统一 14px 视觉尺寸；仅「已置顶」状态用实心强调，避免同组图标重量不一致。

## 剪贴板 · 快捷键与底部提示条（2026-11-12 修订）

### 去掉详情区的复制按钮
详情区**不再提供「复制到剪贴板」按钮**——复制由选中行 + `⏎` 完成，按钮是重复入口。
详情头部只保留「内容类型 + 时间」。

### 行内动作的快捷键

| 动作 | 快捷键 | 依据 |
|---|---|---|
| 复制 | `⏎` | PRD「Enter 执行选中结果或复制选中的剪贴板记录」 |
| 置顶 / 取消置顶 | `⌘P` | 新增。剪贴板窗口无打印功能，Pin 首字母不产生歧义 |
| 复制文件地址 | `⌘C` | PRD「⌘C 统一搜索选中文件时，复制完整文件路径」 |
| 打开文件所在目录 | `⌘⏎` | PRD「⌘Enter 在 Finder 中显示该文件」 |
| 删除 | `⌫` | 按需动作，仅悬停/聚焦行可用 |

### 底部提示条
窗口最下方常驻一条快捷键提示，**只列当前选中行可执行的操作**（PRD：快捷键提示只显示当前状态可执行的操作）；
右侧用低对比度文字补充「文件行另有 ⌘C 复制路径 · ⌘⏎ 在 Finder 中显示」，不抢主动作。

按钮上**不加键位角标**：键位角标压在行内图标上会糊成一团，且 macOS 惯例是把键位交给菜单/提示条。

## 调试记录：一次 CSS 正则误伤（务必注意）

用正则批量删 CSS 规则时发生的事故：

```
原始：.act.pinned .key{...}   /* 详情 */   .detail{...}
误删：re.sub(r'\.key\{[^}]*\}', '') → 删掉 ".key{...}"，留下悬空的 ".act.pinned "
结果：.act.pinned /* 详情 */ .detail{...}  ← 变成复合选择器
后果：.detail 规则整体失效，详情区退回 block 布局、footer 飘到中间
```

**检测方法**（比肉眼可靠）：在页面注入脚本读 `getComputedStyle` 与 `document.styleSheets[0].cssRules`，
确认目标规则是否存在、`display` 是否真的是声明值。这次就是靠 CSSOM 里出现 `.act.pinned .detail` 才定位到。

**教训**：正则删 CSS 时锚定行首（`^\.key\{`）或用完整选择器字符串精确替换，不要用 `.key\{` 这种会匹配到复合选择器尾部的模式。
